# План тестирования

В предпроектном этапе проверяются JSON, все обязательные свойства, ссылки, уникальные ID, ключи ответов и покрытие тем. Игровой сборки пока нет. Остальные проверки применяются по мере появления механик.

## Быстрая проверка фрагмента

В двухкомнатной сборке проверяем один полный цикл. Дойти до платформы, выстрелить или обойти Фонаря, вернуть питание, решить C01-01 и C01-02, освободить Байта, пройти V01-01 и открыть выход. Повторить с ошибкой, без доступа к микрофону и после обновления страницы.

## Приёмочный маршрут полной первой главы

1. Запустить `npm ci` и `npm run dev` после появления каркаса. Открыть игру в Chromium, затем Firefox. Проверить чистый запуск и запуск под статическим префиксом `/igra/` после `npm run build`.
2. Начать игру. Увидеть цель, дойти до укрытия, обойти колонну, остановиться у стены, проверить диагональ, бег и рывок. Выстрел должен попасть в Фонаря или в стену, без выстрела сквозь дверь.
3. Уйти из луча дрона, затем дать себя обнаружить. Проверить патруль, преследование, укрытие, возврат и повтор боя с точки сохранения.
4. Переключить два рубильника в неверном и верном порядке. Питание включает клетку, после её открытия Байт сопровождает героиню. Звуковые и визуальные реакции читаются независимо.
5. Открыть терминал. Управление персонажем останавливается. Для C01-01 отправить «качал», увидеть объяснение ошибки или доступ к подсказке, затем «гудящий». В C01-02 выбрать «мигающий» после перемешивания вариантов. Для C01-03 заполнить два поля, проверив частичную ошибку. Затем решить C01-04, чтобы узел клетки сработал. Закрыть панель и убедиться, что удержанная клавиша не запускает выстрел.
6. У выходного терминала решить C01-05 и C01-06. В режиме с преподавателем проговорить ответ V01-01. Выход остаётся закрытым до подтверждения. В самостоятельном режиме проверить путь без микрофона, с разрешённой записью и с отказом, если браузер поддерживает запись. Удалить запись и убедиться, что отчёт остаётся доступным.
7. Открыть дверь после выполненных условий, сохранить состояние, перезагрузить страницу. «Продолжить» ведёт к безопасной точке. Дверь открыта, предыдущие попытки и статус устной проверки сохранены.
8. Выбрать новую игру в отдельном слоте. Проверить, что прогресс первого слота доступен. Экспортировать учебный отчёт, проверить число попыток и подсказок по главе.

## Техническая проверка банка

Проверка выполняется из корня репозитория. Нужны Python 3.10+ и установленный в выбранном окружении пакет `jsonschema==4.26.0`.

```bash
python scripts/check_question_bank.py
```

Команда валидирует файлы по JSON Schema, проверяет порядок глав и вопросов, совпадение ID и событий узлов, уникальность заданий и ключи выбора. Ожидаемый итог текущей версии — 108 письменных и 18 устных заданий, 18 письменных и 6 устных сюжетных узлов. Филологическую вычитку и браузерную приёмку проводят по критериям выше.
