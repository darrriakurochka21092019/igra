# Архитектура

Приложение запускается как статический сайт. TypeScript и Vite собирают клиент, Phaser управляет миром в canvas, обычный HTML управляет читаемыми меню и учебными формами. Для первой версии достаточно данных в профиле браузера. Авторский JSON используется напрямую через проверку структуры и связей на сборке.

## Источники состояния и событий

Мир использует объекты карты со стабильными идентификаторами `doorId`, `terminalId`, `spawnId`, `itemId`, `encounterId`. Каждая дверь знает список условий, например принят терминал и подано питание. Проигрываемая анимация не служит источником истины. Событие выставляет устойчивый флаг, а отрисовка двери и коллизия восстанавливаются из него при загрузке. Переход между сценами передаёт ID главы, сцены и безопасной точки входа.

Результат письменной попытки содержит ID вопроса, профиль, последовательный номер, ID попытки, верность по полям, уровень подсказки и причину повторного варианта. Учебное событие строится по `content/questions/index.json`: после зачёта всех ID конкретного узла оно помечает узел принятым. Действие в мире выполняется с проверкой физических условий, например с поданным питанием и открытым путём. Индивидуальные эффекты подсказок и ответов отображаются в тексте и состоянии устройства. Событие устного зачёта несёт источник `teacher` или `self`, выбранную рубрику и ID. Сохранение игрового флага по принятому событию и учебного результата завершает одна транзакция.

Canvas получает только игровые события и состояние текущей сцены. HTML-слой получает вопрос, отправляет ответ валидатору и переводит фокус на обратную связь. Пока открыта модальная панель, управление сценой, боевой таймер и клавиши выстрела блокируются, активные клавиши сбрасываются. Закрытие панели возвращает фокус на управление игрой. При уходе вкладки в фон игра и активный таймер ставятся на паузу.

Сюжетные реплики имеют поля `id`, `speaker`, `lines`, `next`, `requires`, `effects`. Устойчивый ID однократной реплики сохраняется. Переход допускает ручную перемотку диалога в журнале. Система проверяет ссылки между картой, текстом, банком, событиями и сохранением до публикации.

## Сохранение

| Хранилище | Данные |
| --- | --- |
| `profiles` | ID слота, выбранный режим, сохранённая версия, время последней игры. Имя профиля может быть нейтральным обозначением ученика. |
| `checkpoints` | Глава, сцена, точка входа, сохранённые сюжетные флаги, открытые двери, предметы, побеждённые боссы, просмотренные записи. |
| `attempts` | Стабильный ID вопроса и ID попытки, номер, исход по полям, использованные подсказки, код навыка, устный источник и отмеченные критерии. |
| Настройки | Громкость, масштаб текста, переназначение клавиш, режим движения, интенсивность эффектов. |

История действий в бою живёт в текущей сцене. При гибели снимаем состояние фаз текущего врага и возвращаем героя к контрольной точке. Автосохранение выполняется при смене устойчивых флагов и при входе в безопасную комнату, а UI показывает успешную запись или доступное повторение. Сохранение имеет версию, последовательный номер и идентификатор профиля. Дубликат события по ID попытки не увеличивает счётчики. Две вкладки используют проверку ревизии в транзакции. При конфликте вкладка приостанавливается и предлагает загрузить актуальную точку. Ошибка записи сохраняет доступ к повтору операции и локальному экспорту, если тот возможен. Миграция тестируется на старых снимках, а при неподдерживаемой новой версии данные доступны для экспорта без перезаписи.

Сервер, облачные профили и онлайн-кабинет преподавателя не входят в стартовую архитектуру. Отчёт формируется на устройстве. CSV для просмотра и JSON для переноса содержат учебные показатели по главам и навыкам. Автоматическая отправка отсутствует. Голосовую запись создаёт отдельный браузерный адаптер только по нажатию и после разрешения. Запись временная, URL аудио освобождается, а микрофон останавливается при завершении, отмене или уходе. Для диагностики достаточно флага, что запись была доступна.

## Бюджет исполнения и решения для первой сборки

- Два слоя данных карты для проверки коллизий и рисования, слои окружения и переднего плана. Декор не создаёт динамические тела без необходимости.
- Один общий пул импульсов для сцены, фиксируем его верхнюю границу. Дрон обновляет обнаружение с ограниченной частотой. Карты проверяют достижимость патрульных точек.
- Частицы и свет ограничены количеством объектов в кадре. При отсутствии WebGL игра использует заранее подготовленный свет, обязательные маркеры остаются видимыми.
- Атласы и звук загружаются по главе. Сценарные и учебные данные первой главы доступны до ввода.
- В первой задаче проверяем запись контрольной точки и восстановление без переключения между устройствами. Режим преподавателя не требует внешнего кабинета, схема позволяет добавить его позже.
